## Encodings — кодування й кінці рядків

Чистий Java без Android — покритий тестами на звичайній JVM ([`test/EncodingsTest.java`](../../test/EncodingsTest.java), 60 перевірок).

Усередині редактора текст завжди має кінці рядків `\n`. Справжні кінці рядків, кодування і BOM запам’ятовуються під час читання й повертаються під час запису — файл зберігається таким, яким був.

### Визначення кодування

```
1. BOM:  EF BB BF → UTF-8 з BOM · FF FE → UTF-16 LE · FE FF → UTF-16 BE
2. UTF-16 без BOM: у перших 8 КБ понад 30% нулів на непарних (LE) чи парних (BE) позиціях
3. Лише ASCII або строго правильний UTF-8 → UTF-8
   (перевіряються надлишкові кодування, сурогати, межі 4-байтових символів)
4. Інакше — однобайтове кодування:
   • «високі» байти стоять поруч із латинськими літерами (> 35%) → Windows-1252
   • для Windows-1251, KOI8-U, CP866: розкодувати й порахувати
       оцінка = (малі кириличні + 0,3 × великі + 0,5 × найчастіші «оеаинтсрвлікдмпуяз») ÷ високі байти
     найбільша оцінка понад 0,45 перемагає, інакше Windows-1252
5. Нульові байти поза UTF-16 → позначка «двійковий» (відкривається лише для читання)
```

Ідея пункту 4: у кириличному тексті слова складаються суцільно з «високих» байтів і здебільшого з малих літер, а в KOI8 і Windows-1251 малі й великі літери лежать у протилежних половинах таблиці. Тому правильне кодування дає найбільше малих літер.

### Підтримувані кодування

UTF-8, UTF-16 LE, UTF-16 BE, Windows-1251, KOI8-U, KOI8-R, CP866, ISO-8859-5, Windows-1252, ISO-8859-1, Windows-1250, ISO-8859-2, Windows-1253, Windows-1254, Windows-1257, GB18030, Big5, Shift_JIS, EUC-KR.

### Кінці рядків

`detectEol` рахує `\r\n`, `\n` і окремі `\r`; переважний варіант стає кінцем рядків файлу, а якщо зустрілося кілька видів — файл позначається як «змішаний». `write(text, enc, bom, eol)` замінює `\n` на потрібні кінці рядків, кодує текст і додає BOM.

`unmappable(text, enc)` рахує символи, яких немає в однобайтовому кодуванні: редактор показує це число перед збереженням і пропонує UTF-8.

## Files — документи й дерево папки

| Метод | Що робить |
|---|---|
| `readBytes(uri, max)` | Читає документ потоком; понад 32 МБ — помилка `TOO_BIG` |
| `writeBytes(uri, data)` | Пише в режимі `"wt"`, далі `"rwt"`, далі `"w"`. Режим з обрізанням важливий: деякі постачальники в режимі `"w"` лишають хвіст старого вмісту, якщо новий коротший |
| `stat(uri)` | Назва, розмір, час зміни, чи можна записувати (`FLAG_SUPPORTS_WRITE`) |
| `list(tree, id)` | Діти папки: папки першими, далі за назвою без урахування регістру |
| `resolve(tree, "a/b/c")` | Шлях → документ, крок за кроком (спершу точний збіг назви, потім без регістру) |
| `create`, `rename`, `delete` | Через `DocumentsContract` |
| `mimeFor(name)` | MIME для перегляду (HTML, CSS, JS, шрифти, картинки, відео, WASM…) |
| `createMime(name)` | MIME для створення: для невідомих розширень — `application/octet-stream`, інакше `script.py` міг би стати `script.py.txt` |

## Store — сесія і резервні копії

Внутрішня пам’ять застосунку, дві папки:

| Папка | Що там | Хто пише |
|---|---|---|
| `files/kv/` | `session` (вкладки, курсори, згортки, закладки, папка проєкту), `settings`, `recent`, `search`, `macros`, `seen` | `Native.kvPut` |
| `files/backup/` | Незбережений текст вкладок, ключ — ідентифікатор вкладки | `Native.backupPut` через 1,2 с після зміни (5 с для файлів понад 20 000 рядків) |

Запис атомарний: тимчасовий файл → `fsync` → перейменування. Тому навіть якщо процес вбито посеред запису, лишається або стара, або нова версія.

## Finder — пошук і заміна в папці

`Finder.Job` працює в пулі з двох фонових потоків і обходить дерево документів.

- **Що пропускається**: файли понад 4 МБ; двійкові розширення (картинки, архіви, шрифти, `apk`, `class`, `so`…); папки зі списку «Пропускати» (за замовчуванням `.git node_modules __pycache__ .gradle .idea .venv venv`); файли, що не підходять під маски (`*.js *.css`).
- **Як шукає**: кожен файл декодується з визначенням кодування, пошук іде по рядках виразом `java.util.regex`. «Ціле слово» — `(?<![\p{L}\p{N}_])…(?![\p{L}\p{N}_])`, тож працює з кирилицею. Без регістру — `CASE_INSENSITIVE | UNICODE_CASE`.
- **Результати** надсилаються порціями не частіше ніж раз на 250 мс: шлях, кількість, до 300 рядків з першим збігом і фрагментом тексту навколо. Загальна межа — 5 000 збігів.
- **Заміна** обробляє лише файли зі списку `paths`, тобто ті, що користувач щойно бачив у результатах. Кожен файл записується в його власному кодуванні, з BOM і кінцями рядків. У звичайному режимі заміна екранується `Matcher.quoteReplacement`, у режимі regex працюють `$1`.
- `cancel(id)` зупиняє обхід після поточного файлу.

## Server — віртуальні сайти

`MainActivity.Client.shouldInterceptRequest` віддає всі запити до двох доменів, яких насправді не існує. У мережу ці запити не йдуть.

| Домен | Шлях | Звідки |
|---|---|---|
| `appassets.androidplatform.net` | `/www/…` | `assets/www` — сам редактор |
| `preview.appassets.androidplatform.net` | `/__kod/hook.js` | перехоплювач консолі |
| | будь-який інший | спершу текст відкритих вкладок (`previewSet.files`), далі файли папки проєкту за відносним шляхом; `/` і папки → `index.html` |

У кожну HTML-сторінку перегляду одразу після `<head>` вставляється `<script src="/__kod/hook.js">`: він пересилає консоль і помилки в редактор через `postMessage` (див. [Інструменти](tools.md#запуск-і-консоль)). Знайдені шляхи кешуються до наступного `previewSet`. Відповіді мають `Cache-Control: no-store`, щоб «Оновити» завжди показувало свіжий вміст.
